One repeated action

Show the current pipeline → explain one edit → make it → run → inspect the actual output. Ask what now enters the learner before revealing the result.

Source inputs and model branches are different. S1/S2/S3 are measurements; B1/B2 are predictors. Early fusion connects several source inputs to one B1 model. Use Connect to add a measurement; New branch creates another predictor. Late fusion deliberately uses one model branch per source. A mid network B1 contains its own internal source encoders. Use the actual connections and Merge kind control, not an imagined free drag of the fusion point.

The session uses 21 minutes of support, 17 minutes of live editing and 2 minutes of discussion. The three live sequences below take six, five and six minutes.

Load the three teaching collections and browser runtimes before the clock starts. Use the editor's presets as editable starting documents. The three panels provide presets and building blocks, model branches with their source inputs, and the selected node's settings. Select a card to edit it.

Early

Source-specific steps → combine variables → one predictor.

Late

One predictor per branch → combine predictions.

Intermediate

Learn a representation per source → combine learned features → common head.

What enters the model?

Early · variables

Raman 48 + NIRS 64 + MIR 56 = 168 variables. The 96 calibration observations form a 96 × 168 matrix. A common PLS with three components predicts the target.

Late · predictions

Three model branches B1/B2/B3 each predict the same target. The native fixed mean combines three predictions per observation, aligned by sample ID.

Mid · learned features

Inside one joint B1 network, NIRS conv1d and image conv2d encoders each produce an embedding of size 6. Their 12 concatenated features enter a shared head with 8 hidden units before the target output.

Stacking: three sources × PLS/Ridge = six OOF prediction columns for a Ridge combiner. Each training prediction is made by a model that did not fit that row or its group.

MB-PLS: the head retains block widths [48, 64, 56]. The demonstrated NIPALS profile centers blocks and uses equal super weights; it is a specific multiblock model, not a guarantee of improvement.

Demo 1 · Raman + NIRS + MIR

Six minutes

  1. Open Early fusion. Trace Raman, NIRS and MIR through their own processing chains into the common PLS. Run the starting draft with Run edited pipeline.
  2. Disconnect MIR. Keep the remaining source chains and model settings explicit. Inspect the changed source inputs, then run that draft. Compare these two runs before changing anything else.
  3. Restore the original three-source draft. Select its B1 PLS head and change Components from 3 to 6. Run this separately so source selection and model capacity can be distinguished. Inspect a source processing node separately if time remains.
  4. Restore the starting run from history. Show that the exact saved document returns to the editor, rather than resetting to an unrelated preset.
  5. Open Late fusion. Point to the separate source models and the fixed prediction mean. Ask what enters that merge: predictions, rather than the original spectral columns.

The current teaching widths are Raman 48, NIRS 64 and MIR 56. A two-source draft is a different experiment from the three-source draft. More sources do not guarantee a lower error.

Demo 2 · NIRS + genetic markers

Five minutes

  1. Load the paired case and a late preset. Follow one observation through its NIRS trace and marker row.
  2. Inspect each branch. Keep spectral steps on NIRS; the markers are unordered numeric dosages, without a wavelength axis.
  3. Change one branch model. Replace the genetic branch's PLS head with Ridge. Keep the other branch and fixed mean visible, then use Run edited pipeline.
  4. Read and restore. Compare the actual current output with the starting draft, then restore it from history.
  5. If time remains, show stacking. Replace the fixed average with a learned combiner using the supported stacking preset, then inspect its base predictions and final Ridge.

The supplied example has 16 dosage markers and 60 materials with two observations each. A VCF GT source becomes 0/1/2 dosage; an explicitly mapped dosage CSV is another admitted route. Biological groups remain visible in the experiment.

A learned stack needs prediction features made by models that did not fit those rows or groups. State this at the combiner, then return to the concrete pipeline.

Demo 3 · NIRS + images

Six minutes

  1. Select the same observation in both views. Show its actual 12 × 12 grayscale image and paired NIRS spectrum.
  2. Open the early baseline. The common PLS receives 144 ordered pixels and 64 spectral variables after their source processing.
  3. Open the intermediate pipeline. Inspect the 2D image branch, 1D spectral branch and learned feature merge. Their geometry follows the actual source shapes.
  4. Edit the supported embedding size. Inspect the neural head's settings, change one value, and use Run edited pipeline. Keep the remaining settings fixed.
  5. Read the actual result. Describe what happened even if the compact network is worse than PLS. Restore a saved draft or export it for a later run.

The model learns branch and head weights together. It is trained from scratch; this example is not a pretrained image-backbone demonstration.

Save, restore and rerun

  1. Select a completed run in the history and use Restore to recover its actual editable pipeline.
  2. Export its pipeline JSON, then import that file into the matching dataset.
  3. Inspect the restored source inputs, transforms, heads and merge; use Run edited pipeline again.

The exported document uses nirs4all.multimodal-pipeline.v1. It stores the editable pipeline description. Do not describe it as an exported trained predictor. If a native recipe view is shown, use the exact generated document rather than an invented code example.

For a hybrid route, the meta-model receives both explicit source features and OOF prediction inputs. Show those distinct inputs before running it; a merge's meaning follows what enters it.

Read the effect of your edit

Name the before and after drafts. Confirm which source, processing step or model changed. Read their actual current outputs under the same comparison scope. Explain the observed effect without promising improvement.

In the spectral demonstration, compare all sources with PLS 3, MIR disconnected with PLS 3, then all sources restored with PLS 6. This simulation illustrates how source contribution and model capacity interact; it does not establish that MIR is a bad source. Compare OOF and keep the held-out test out of these adjustments.

Do not attach the earlier default score table to an edited pipeline. Keep labelled recorded runs as a backup; if a run refuses or is cancelled, say so and use the backup honestly.
